## 1. Purpose

E3 adds a local owner-only read-only API facade over persisted K-Geopolitical Monitor runtime state so a future private GPT Action can retrieve actual backend state without fabricating data or substituting public-web research.

The API is an access layer over existing project-local canonical state. It is not a new canonical store, monitoring host, verification engine, or production deployment.

## 3. API Scope

Initial scope is read-only.

Protected owner-state endpoints expose:
- persisted state summary;
- recent alerts;
- alert detail;
- active monitoring watches;
- monitoring runs;
- source collection attempts;
- unavailable/stale/degraded source state;
- latest operational coverage snapshots.

Health endpoint:
- /health remains accessible independently from owner authentication.

OpenAPI operation IDs are explicit so the interface can be consumed by a future GPT Action without relying on autogenerated unstable names.

## 4. Authentication Contract

Authentication model:
- HTTP Bearer;
- owner token injected at runtime;
- token is stripped/validated during app creation;
- empty token fails closed;
- token is not written to repository state;
- token is not written to project database state;
- comparison uses secrets.compare_digest.

Required behavior:
- missing bearer credentials -> HTTP 401;
- invalid bearer credentials -> HTTP 401;
- HTTP 401 responses include WWW-Authenticate: Bearer;
- valid owner bearer credentials -> protected endpoint executes normally.

## 5. Read-Only Storage Contract

The E3 reader opens the existing project-local SQLite runtime database through a read-only URI and enables PRAGMA query_only.

Mandatory storage rules:
- runtime storage remains PROJECT_LOCAL_ONLY;
- no shared runtime database;
- no direct database exposure to GPT clients;
- no API write endpoints in E3 initial scope;
- no GET request may mutate canonical project state.

The regression suite explicitly compares persisted record counts before and after a protected endpoint sweep.

## 6. Persisted-State Semantics

Alert output includes persisted finding importance and, when traceably resolvable from one claim reference, persisted verification state.

Degraded-source output combines persisted collection-attempt availability and the latest E2 source reputation state without converting source reputation into claim truth.

Coverage output exposes persisted coverage_ratio and coverage_confidence with their existing Phase 11 semantics. Coverage confidence remains distinct from claim verification confidence.

The persisted monitoring_runs model does not currently distinguish unattended execution provenance. Therefore:
- last_unattended_cycle_at = null;
- unattended_cycle_instrumentation = NOT_INSTRUMENTED;
- the API does not infer or fabricate an unattended timestamp.

## 7. Fail-Closed Rules

E3 preserves the following mandatory boundaries:
- public-web research cannot substitute for unavailable persisted backend state;
- unavailable backend state must remain explicit;
- missing instrumentation must remain explicit;
- no backend state may be fabricated;
- source status does not become claim truth;
- coverage confidence does not become verification confidence;
- API presentation cannot strengthen upstream evidence state.

## 9. Validation Failure and Root Cause

Pre-fix canonical failure:
- GitHub Actions run 33245112923;
- job 99081132328;
- 249 passed / 5 failed;
- all failures were in tests/test_backend_action_api.py.

Observed primary symptom:
- protected endpoints returned HTTP 422 for both missing and valid Authorization states.

Secondary test failures were consequences of parsing FastAPI validation-error payloads as normal endpoint payloads.

Root cause:
- backend_action_api.py used `from __future__ import annotations`;
- create_action_app defined a local `OwnerAuth = Annotated[str, Depends(authorize)]` alias;
- under the CI FastAPI/Starlette/Pydantic environment, postponed evaluation prevented the local dependency annotation from resolving correctly;
- FastAPI interpreted the endpoint `_` parameter as a required query parameter and returned HTTP 422.

The failure was independently reproduced with the validation payload location `query -> _`.

Fix:
- remove postponed annotation evaluation from backend_action_api.py;
- preserve the existing HTTPBearer dependency, OwnerAuth alias, bearer semantics and endpoint contract unchanged.

This is intentionally a minimal compatibility repair rather than a redesign of authentication.
