# Phase 20 — Source Coverage & Collection Quality Design

Date: 2026-09-11
Status: `DESIGN_ONLY / IMPLEMENTATION_NOT_STARTED`
Gate target: `P20_GLOBAL_SOURCE_COVERAGE_VALIDATED`

## 1. Objective

Make KGM coverage measurable so the system can state not only what it sees, but also where its information picture is weak, stale, dependent on a single origin, or operationally unavailable.

This design builds on validated Phase 12 source-network foundations and Phase 13 provenance/independence semantics. It does not alter factual verification rules.

## 2. Non-negotiable semantic boundaries

Coverage and verification are different dimensions.

```text
SOURCE_COUNT != INDEPENDENT_ORIGIN_COUNT
PUBLISHER_COUNT != CORROBORATION_COUNT
LANGUAGE_COUNT != INDEPENDENT_EVIDENCE_COUNT
HEALTHY_SOURCE != TRUE_CLAIM
OFFICIAL_SOURCE = authoritative for its own statement, not automatically for the underlying event
MISSING_SOURCE != EVIDENCE_OF_ABSENCE
COVERAGE_CONFIDENCE != FACTUAL_VERIFICATION_CONFIDENCE
```

P20 must reuse canonical P13 provenance/independence semantics rather than introducing a second truth model.

### P20.2 — Coverage matrix

For each monitored region/country, calculate coverage across:

- source type;
- language;
- authoritative vs reporting sources;
- primary/local vs external reporting;
- availability/health;
- freshness;
- redundancy by independent origin.

The matrix should support explicit states such as:

```text
SUFFICIENT
THIN
MONOCULTURE_RISK
STALE
UNAVAILABLE
UNKNOWN
```

Gate: `P20_2_COVERAGE_MATRIX_VALIDATED`

### P20.3 — Collection-quality metrics

Measure:

- acquisition success rate;
- collection latency;
- parse failure rate;
- freshness age;
- missing expected updates;
- consecutive failures;
- source downtime;
- item duplication rate;
- syndication/copy concentration where provenance permits;
- time-to-first-observation for selected benchmark events.

Gate: `P20_3_COLLECTION_QUALITY_METRICS_VALIDATED`

### P20.4 — Monoculture and independence-risk analysis

Detect cases where apparent diversity is generated by:

- many outlets copying one wire;
- translations of the same report;
- official statement republication;
- syndication networks;
- cross-posted public social content;
- multiple adapters ingesting the same underlying feed.

Output must use P13 independence vocabulary:

```text
INDEPENDENT
NOT_INDEPENDENT
UNKNOWN
MIXED
```

Gate: `P20_4_SOURCE_MONOCULTURE_RISK_VALIDATED`

### P20.5 — Gap and blind-spot detection

Generate bounded coverage warnings for:

- no active source in a required source class;
- missing local-language perspective;
- all sources stale/unavailable;
- single-origin dependency;
- excessive collection latency;
- source portfolio concentrated in one geopolitical bloc or one distribution chain;
- expected authoritative channel missing.

Warnings describe information risk; they do not infer that an event did or did not occur.

Gate: `P20_5_COVERAGE_GAP_DETECTION_VALIDATED`

### P20.6 — Operator projection and validation matrix

Provide an owner-facing read-only projection:

```text
INDEPENDENT_ORIGIN_DIVERSITY
STALE_SOURCES
UNAVAILABLE_SOURCES

```

## 4. Coverage dimensions

### Geography

At minimum support:

- global region;
- country;
- optionally subregion/theater when operationally meaningful.

Do not claim exhaustive global coverage merely because every region has at least one source.

### Language

Track both publication language and translation state. Machine-translated or republished material remains the same underlying origin unless provenance proves otherwise.

### Source role

Separate at least:

- authoritative self-reporting;
- independent reporting;
- contextual analysis;
- structured/telemetry data;
- public social/first-person material.

### Availability

Maintain distinct states for governance and observed operation:

```text
APPROVED / DISABLED / RETIRED
HEALTHY / DEGRADED / UNAVAILABLE / STALE / UNKNOWN
```

A source may be governance-approved but operationally unavailable.

## 5. Proposed scoring approach

P20 should avoid one opaque global score. Prefer a vector of explainable measures:

```text
geographic_breadth
language_breadth
source_type_breadth
independent_origin_diversity
freshness_health
collection_reliability
latency_quality
monoculture_risk
```

A summary classification may be derived from this vector, but raw dimensions must remain available for audit.

## 6. Minimal data model direction

Design-only candidate entities:

```text
source_coverage_profile
coverage_requirement
coverage_observation
collection_quality_observation
coverage_gap
source_dependency_cluster
```

No migration is authorized by this document. Any future schema migration requires a separately reviewed implementation step.

## 7. Benchmark strategy

P20 validation should use controlled benchmark sets rather than only live anecdotal observations:

- known multilingual geopolitical events;
- authoritative statement plus downstream syndication;
- source outage/staleness fixtures;
- duplicated wire-service chains;
- local-language-only discovery cases;
- contradictory but independently sourced reports;
- quiet periods where source health must still be distinguishable from no events.

## 8. Acceptance criteria

P20 may close only when:

- coverage is measurable by geography, language and source type;
- operational source health is represented separately from portfolio approval;
- source monoculture is detectable;
- independent-origin diversity is not approximated by domain count;
- stale/unavailable sources cannot make the system report false calm without a coverage warning;
- material gaps are owner-visible;
- all metrics are reproducible from canonical source/provenance data;
- P13 factual-verification semantics remain unchanged;
- no unapproved paid/shared-runtime dependency is introduced.
